files to `4807b1d`, ran the new tests, saw them fail, and restored the fix. The suite went from
**1,035 tests in 105 files to 1,456 in 121**. `pnpm lint`, `typecheck`, `test`, `build`,
`handbook:check`, `check:examples`, `check:docker`, `version:check`, `check:licenses`, the chart
check and `pnpm audit --prod` all pass. The manifest shrank by 27 characters; no tool description,
argument description or instructions text grew.

## Decided differently from, or beyond, the report

- **The release is now two jobs.** This reverses the documented "one job, deliberately" decision:
  the checks run every devDependency, and they no longer do it in the job holding the publish
  tokens. The workflow header and `deployment.md` say why.
- **pnpm was already pinned** in the Dockerfile; finding 47 was wrong on that point. The version
  moved into one `ARG`, and `check:docker` now fails if it drifts from `packageManager` or a base
  image loses its digest.
- **A free field that did not store fails the write** rather than returning a flagged success — the
  descriptions promise it, and a result without an error gets summarised as "done".
- **`MCP_MAX_SESSIONS_PER_SUBJECT` is refused unless `AUTH_MODE=oauth`** — under `none` and
  `bearer` every caller is one subject.
- **Beyond the report:** a call still running when its conversation ended could send its
  remaining requests as the service account; each call now keeps the session it started on. The
  OAuth verifier's logger was never wired in production; it is now. The credential-guard exemption
  for `list-assigned-work.ts` is gone, because it reaches the directory only through `findPerson`.

## Known limits of the fixes

- A 401 re-opens the person's session even when the 401 came from the service account's own call.
- Two initializes by one subject at the same instant can briefly exceed the per-subject limit; a
  session ended by the client's own DELETE starts a release shutdown does not track.
- With stdio and OAuth both on, the stdio conversation also gets the OAuth instructions.
- The quick-action probe with `shouldSave:false` and `SendEmail` is still unmeasured.
